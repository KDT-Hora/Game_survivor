## 既存 rimrim の調査結果(§21)と方針
- 実体: C++17 / SFML 3 / ImGui の約1100行。ECS(Entity/Component/System/EventBus/QueueManager)、MapManager、Scene。
- 流用: SFML のビルド済みバイナリ(`third_party/SFML`。DLL 非同梱のため**静的リンク**)、ECS の骨格、EventBus、QueueManager、タイル/地形の考え方。
- 置換・修正した点(問題と理由):
  - `SystemManager` は `hash_code()` を uint8 に切り詰めた `unordered_map` で、衝突すると System が消え、実行順も不定 → 登録順に実行する `vector` に変更(§16 の処理順を保証)。
  - `ComponentArray::GetData` が範囲外を検査しない → assert 追加、疎配列(index→dense)に変更。
  - System ループ中の `DestroyEntity` が `mEntities` を壊す → `DestroyLater` + フレーム末尾 `Flush` に統一。世代付き ID で古い ID を無効化。
  - `Tile` が単一の Entity リスト・未初期化フィールドを持つ → `MapSystem` に置換(Terrain / 岩 / 壁の3層、用途別 Blocks 属性、イベント発行)。
  - `InputManager` はキーボードのみ → マウス照準・右クリックを app 層で扱う。
  - ImGui は当初採用しなかったが、のちにデバッグ用として採用した(末尾の「ImGui のデバッグモード」を参照)。HUD は `sf::Text` のまま。
- §21 の確認項目: MapManager が複数レイヤー対応か → 不可、置換。System 実行順 → 修正で可。自由移動とタイル障害物の両立 → 円 vs タイル AABB で実装(`MoveAndSlide`)。生成・破棄の安全なタイミング → Queue/Flush。EventBus がマップ変更通知に使えるか → 使える(`OnObstacleMoved` ほか4種)。

## 仕様 §22 の未確定事項に対して実装で選んだ内容(プレイテストで見直す)
- 境界判定: 岩・壁・地形はタイル AABB、プレイヤー・敵は円。軸ごとに移動を解決して壁面を滑る。壁が円に重なって置かれた場合は `Depenetrate` で押し戻す(プレイヤーが設置タイルに重なる状況を作らない)。
- 敵同士: 空間ハッシュで近傍を取り、重なりに応じた分離のみ(押し合いはしない)。
- 押し出しの割当: 使える候補が少ない対象から、最も近い空き(ユークリッド距離、同距離は 上→右→下→左→斜め の固定順)を重複なしで確保。1体でも確保できなければ全体キャンセル。敵はプレイヤーのタイルへ押し出さない。
- 距離比較: ユークリッド。
- 経路探索: A*(8方向、角抜けなし)。1フレーム6本まで、無効化された経路を最優先、遠距離は頻度 1/3。到達不能なら最接近点まで進んで待機(うろつかない)。見通しがあれば直進。
- 壁を壊せる/岩を押せる能力は敵データ(`breaks_walls` `pushes_rocks`)で表し、経路コストに反映。押せない岩は一定時間後に壊す。
- 素材は、マップ上に散らばるアイテム(連続座標)+敵ドロップとして実装(資源ノードの採取は未実装)。
- 弾は岩・外周で止まり、プレイヤーの壁は貫通する(`wall.basic.blocks_projectile`)。
- 勝敗: 規定時間でボス出現、ボス撃破でクリア、プレイヤー死亡でゲームオーバー。逃げ続けるだけではクリアできない。

## 追加対応(フェーズ制・新攻撃手段) — 実装で選んだ内容(未承認)
- System はフェーズ(Prepare, Control, Interact, EnemyThink, EnemyPath, EnemyMove, Build, Attack, Hazard, Damage, Resolve, Reward, Progress)に所属。フェーズ間のみ順序を持つ。同フェーズ内の System は互いの書き込みを読まない。`EnableIntraPhaseShuffle` で実行順を毎フレーム乱せる(テストの Fixture は常に有効)。
- 攻撃手段は `Arsenal`(スロットの配列)で持つ。最初はボルトのみ。強化 `grant_weapon` で獲得、再選択でレベル+1(威力+30%・クールダウン-8%、下限 0.4倍)。
  - 時限爆弾: 自動で足元に設置(3.5秒ごと)、2.5秒後に爆発、半径90内の敵に1回ダメージ。プレイヤーには当たらない。
  - 貫通ビーム: カーソル方向へ1.6秒ごとに発射。敵は貫通し、同じ敵には1回だけ当たる。岩・外周で止まる。プレイヤーの壁は通過する。
  - 玉を増やす: ボルトが `1+N` 発になり、近い敵から順に別々の敵へ飛ぶ。敵が足りなければ少し角度をずらして同じ敵へ。
- 爆弾・ビームの数値は仮置き。`data/balance.cfg` で調整できる。

## 追加対応(スライム画像)— 実装で選んだ内容(未承認)
- 画像は `data/Image/スライム/<色>/0..3.png`(32×32、4コマ)。敵の種類ごとに色を `enemy.<名前>.sprite` で指定、描画サイズは `draw_size`、速さは `sprite.anim_fps`。
- コマは時間(ゲーム時間。一時停止で止まる)で進め、個体ごとに位相をずらす。補間なし(ドット絵)。画像が読めなければ従来の円で描く。
- 当たり判定の半径は見た目と別。見た目に合わせて通常 10→12、大型 14→15 に変更。ボスは経路探索(1マス幅の通路)のため半径 15 のままで、見た目は 72 と大きい。
- 使っていない素材: 黄・青・赤紫(今後の敵種用)、`チップ/`(オレンジ・ピンク・水色を含む1枚絵)、`.ico`。

## 追加対応(rimrim の作者が読める構造への書き換え)— 実装で選んだ内容(未承認)
rimrim の実コード(`tutorial/` 配下)を確認し、その書き方に寄せた。機能(フェーズ制・新武器・スライム・仕様の建築/岩押しの規則)は残し、仕組みを簡素にした。
### 構造の変更(rimrim に合わせた点)
- System は `src/game/Systems/XxxSystem.h` に **1 System = 1 ファイル**(rimrim の `ECS/Systems/` と同じ)。各 System は `Init()` で必要な Component の組を返し、`Update()` で処理する。登録は `src/game/ECSRegister.cpp`(rimrim の `ECSRegister.cpp` と同じ役割)に集約。
- 名前: `MapSystem` → `MapManager`、`Simulation` → `GameSession`(rimrim の名前)。
- 攻撃手段は共通の親 `WeaponSystem`(Arsenal を巡回し、クールダウンが終われば `Fire()` を呼ぶ)を継承。ボルト/爆弾/ビームは `Fire()` だけを書く。
- 長い Update は、意味のまとまりごとの private 関数に分けた(例: 敵 AI の壁攻撃・岩押し、弾の貫通/通常命中)。
### 簡素化した点と、挙動が変わるところ
- **世代付き Entity ID を廃止**。ID は番号のみ+生存フラグ。ID は待ち行列の最後に戻すので、破棄直後に再利用されることはない(20000 個を使い切るまで)。古い ID を長く持ち続けると、理論上は別の Entity に当たりうる(今は `g.boss`、貫通弾の命中済みリストなどが該当。いずれも寿命が短いか、再利用まで十分長い)。
- **経路探索の優先制御を簡素化**: 「経路が壊れた敵を最優先」「遠距離は頻度 1/3」「経路の有効性検査(`PathStillValid`)」を廃止。マップが変わったら経路を使う敵は全員が再探索を要求し、プレイヤーに近い順に1フレーム `path.budget` 本まで探索する。壁/岩を動かした直後は、遠い敵の再探索が少し遅れる(今のところ到達までの挙動に支障なし)。`path.far_distance` `path.far_interval_mul` は設定から削除。
- **押し出しの割当を単純化**: 「使える候補が少ない対象から」→「敵を先、アイテムを後(同種は ID 順)」。全員が置けなければ全体取りやめ(§6.3)は変えない。まれに、組み合わせ次第で割当が見つかるのに失敗する場合がある(周囲8マスがほぼ塞がっているとき)。
- テスト: 経路の有効性検査のテストを削除(67→66件)。それ以外の挙動テストは変更なし。
### 残した複雑さ(外すと不具合が戻るもの)
フェーズ制+フェーズ内シャッフル(ユーザー要望)、遅延破棄(`DestroyLater`+`Flush`)、MapManager の占有一元管理とイベント、A* の角抜け禁止・到達不能時の最接近点、岩を押し潰さない判定、弾の線分判定(半径 0.5)、入力エッジの保持。
### 未実施
- Component 名の `○○Component` 化(rimrim は `TransformComponent` など)。変更箇所が多く、`Player` `Bomb` などが enum 名と衝突するため見送り。
- 空間ハッシュの廃止(350 体で 0.2ms/step を保つために残した)。

## 追加対応(最小の敵も壁を壊す・遠距離敵)— 実装で選んだ内容(未承認)
- 通常敵(最小)も壁を壊せる: `enemy.normal.breaks_walls = 1`、`wall_dps = 8`(大型 25 / ボス 60 より弱い。基本壁 hp100 を約12秒)。経路探索も壁を「コスト付きで通れる」扱いになるため、壁で囲まれても到達する。壁の強さはこれまでより相対的に下がる(要バランス確認)。
- 遠距離敵 `shooter`(黄スライム): hp14・射程260px。射程の85%まで近づくと止まり、2.2秒ごとにプレイヤーへ弾(ダメージ6、速度200)を撃つ。壁は壊さない・岩は押さない。出現は 60 秒から(割合 8% +1分ごとに 3%)。
- 敵の弾(`Projectile::hostile`): プレイヤーに当たると消えてダメージ。**壁に当たると壁にダメージを与えて消える**(自分の弾は壁を通過するが、敵の弾は通らない)。岩・外周でも止まる。岩などが射線上にあるときは撃たない。無敵時間の対象外。描画は紫の玉。
- 新 System `EnemyShootSystem`(Attack フェーズ)。数値はすべて `balance.cfg`(`enemy.shooter.*`、`spawn.shooter_*`)。全敵に `range` `shot_*` の項目を追加(近接は `range = 0`)。
- テスト: 70件(最小の敵が壁を壊す、遠距離敵の射撃・壁での停止・岩越しに撃たない)。壁を迂回するテストは `enemy.normal.breaks_walls = 0` で行う。

## 追加対応(ImGui のデバッグモード)— 実装で選んだ内容(未承認)
- 先の「ImGui は採用しない」を変更し、デバッグ用に採用した。`third_party/imgui`(Dear ImGui 1.92.5 WIP)と `third_party/imgui-sfml` は rimrim から取り込んだもの。`terrain_survivor` にだけ入れ、`ts_core`(ゲーム本体)には入れない。DockSpace は使わない(ゲーム画面を覆わないため)。`imgui.ini` は作らない。日本語はシステムの Meiryo 等を読み込む。
- F1 でデバッグモード。3つのウィンドウ(`src/app/DebugUi.*`):
  - システム: 当たり判定の表示(円・通行不可タイルの枠)、敵の経路の表示、ゲーム速度(0〜10倍、プレイ中のみ)、時間+30/+60秒、新しいラン。
  - プレイヤー: HP/最大HP、無敵、移動速度・攻撃力・攻撃速度・追加の玉・被ダメージ軽減・拾う範囲・岩を押す速さ・壁耐久・建築コスト減、素材、レベルアップ、攻撃手段のレベル、強化の直接獲得。
  - 敵の出現: 自然出現の ON/OFF、出現ペース・上限・距離・種類ごとの割合・ボス出現時間(すべて実行中に変更可)、種類ごとの数の表示、手動で出す(プレイヤーの近く)、全敵を倒す(HP0=ドロップあり、ボスならクリア)/ 全敵を消去(ドロップなし、ボスは残す)。
- 数値の変更は「いまのラン」だけに効く(新しいランは balance.cfg の値に戻る)。デバッグモードを抜けると、倍速・無敵・出現 OFF は解除される。ImGui がマウス・キーボードを使っている間は、ゲームへ入力(右クリックの建築・WASD など)を渡さない。
- ゲーム層の変更は `GameContext::spawnEnabled` の1つだけ(出現 System が見る)。テスト `spawn_can_be_switched_off_for_debugging` で確認。
- 確認用 CLI: `--debug-draw`(当たり判定を重ねて描く)、`--debug-paths`(経路も)、`--debug`(最初からデバッグモード。ウィンドウ起動時)。
